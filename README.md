# ElviaService

Telegram-бот Elvia для супроводу терапії: профіль пацієнта, призначення лікаря, контроль ваги, щотижневі check-in та оформлення замовлень. Інтерфейс — українською мовою.

## Можливості

### Клієнт

- Реєстрація: ПІБ, телефон, зріст, початкова й цільова вага; посилання на медичну анкету.
- Профіль: Telegram ID під назвою «ID», ПІБ, телефон, зріст і поточна вага.
- Активна й запланована терапія, історія дозувань і загальний результат.
- Оновлення ваги з підтвердженням та зображення прогресу.
- Check-in: вага, самопочуття, апетит, побічні реакції, прийом дози та необов’язкові заміри тіла.
- Замовлення на 1, 2 або 4 тижні, дані доставки, реквізити, завантаження квитанції та історія замовлень.
- Повідомлення після підтвердження оплати, посилання на лікаря й інформаційний канал.

### Адміністратор

- Пошук пацієнта за ПІБ або телефоном.
- Список усіх користувачів по 10 на сторінці, картка пацієнта та повернення до списку.
- Перегляд результатів check-in та історії терапії.
- Створення дозувань: препарат, кількість мг, ціна за тиждень і підтвердження.
- Видалення дозувань через інлайн-список із пагінацією та підтвердженням. Дозування приховується для нових призначень; наявна терапія й замовлення зберігаються.
- Призначення дозування з датою початку та повідомленням пацієнту.
- Перегляд замовлень, квитанцій і зміна статусів.

## Технології та вимоги

- **Python 3.14** — версія локального середовища та Docker-образу.
- **aiogram 3** — Telegram API та діалоги.
- **SQLite** — користувачі, терапія, дозування, вага, замовлення та check-in.
- **APScheduler 3** — активація призначень і нагадування.
- **Pillow** — зображення прогресу.
- **python-dotenv** — конфігурація; **tzdata** — часові пояси.

Потрібні токен Telegram-бота, доступ до Telegram API та числовий Telegram ID адміністратора. Для контейнерного запуску — Docker і Docker Compose.

`requirements.txt` у UTF-8 містить зафіксовані версії основних і транзитивних залежностей, перевірені в локальному середовищі. Redis у поточному запуску не використовується. SQLite входить до стандартної бібліотеки Python.

## Налаштування

Скопіюйте `.env.example` у `.env` і заповніть значення. Усі команди нижче виконуються з кореня проєкту.

| Змінна | Призначення |
| --- | --- |
| `BOT_TOKEN` | Обов’язково. Токен бота від BotFather. |
| `DOCTOR_ID` | Обов’язково. Один числовий Telegram ID адміністратора, без `@` та без ком. |
| `URL_GOOGLE_FORM` | Обов’язково. Посилання на медичну анкету. |
| `DOCTOR_URL` | Обов’язково. Посилання на Telegram-профіль лікаря. |
| `CHANNEL_URL` | Обов’язково. Посилання на інформаційний канал. |
| `CHECKIN_TEST_BUTTON_ENABLED` | `true` показує кнопку ручного тестування check-in; для звичайної роботи встановіть `false`. Типове значення — `true`. Автоматичні нагадування від прапорця не залежать. |
| `PAYMENT_TEST_MODE` | `true` додає попередження не здійснювати оплату. Типово — `false`. Самі реквізити цей прапорець не підміняє. |
| `PAYMENT_RECIPIENT` | Отримувач платежу; заповніть перед прийманням замовлень. |
| `PAYMENT_IBAN` | IBAN; пробіли прибираються, літери переводяться у верхній регістр. |
| `PAYMENT_PURPOSE` | Призначення платежу. Типово: `Оплата замовлення Elvia`. |

`.env` містить секрети й виключений із Git. Порожні платіжні реквізити не блокують запуск: у повідомленні можуть відображатися заповнювачі, тому перевірте їх перед використанням.

## Локальний запуск

### Windows / PowerShell

```powershell
py -3.14 -m venv .venv
Copy-Item .env.example .env
New-Item -ItemType Directory -Force data
```

Заповніть `.env`, потім виконайте:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe main.py
```

Активація середовища не потрібна: команди використовують його Python напряму.

### Linux / macOS

```bash
python3.14 -m venv .venv
cp .env.example .env
mkdir -p data
```

Після заповнення `.env`:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
.venv/bin/python main.py
```

Каталог `data` потрібно створити до першого запуску. Таблиці та передбачені кодом оновлення схеми створюються автоматично через `init_db()`. База знаходиться в `data/db.db`. Для зупинки процесу натисніть `Ctrl+C`.

## Docker Compose

Створіть і заповніть `.env`, створіть каталог `data`, потім запустіть:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Керування:

```bash
docker compose ps
docker compose restart bot
docker compose down
```

Після зміни коду чи залежностей повторіть `docker compose up -d --build`. Після зміни `.env` виконайте `docker compose up -d --force-recreate`: простий `restart` не перечитує середовище контейнера.

Монтування `./data:/app/data` зберігає базу на хості. Зупинка чи пересоздання контейнера не видаляє цю папку. Бот використовує long polling; публічний HTTP-порт не потрібен. Запускайте один екземпляр на токен.

## Перші кроки

1. Відкрийте бота в Telegram та надішліть `/start`.
2. Пройдіть реєстрацію; після неї свій числовий ID можна побачити в профілі.
3. Вкажіть ID адміністратора в `DOCTOR_ID`, перезапустіть бота після зміни налаштувань.
4. Надішліть `/admin` з облікового запису адміністратора.
5. Відкрийте «💉 Дозування» → «➕ Додати», введіть препарат, мг і ціну за **один тиждень без знижки**, підтвердьте. Для видалення оберіть конкретне дозування в цьому ж списку.
6. Відкрийте пацієнта через пошук або «👥 Усі користувачі» та призначте дозування з потрібною датою.
7. Перевірте клієнтські розділи терапії, профілю та оформлення замовлення.

Нова база не наповнюється дозуваннями автоматично — створюйте їх через адмін-панель. Локальний `seed.py`, якщо наявний, призначений для демонстраційних даних і не є частиною звичайного запуску.

## Команди та навігація

| Команда | Дія |
| --- | --- |
| `/start` | Початок роботи або повернення зареєстрованого користувача до меню. |
| `/menu` | Вихід із поточного діалогу й повернення до клієнтського меню. |
| `/cancel` | Скасування поточного діалогу й повернення до клієнтського меню. |
| `/admin` | Панель лікаря для ID, зазначеного в налаштуваннях. |

Вихід із діалогу не видаляє вже збережені замовлення чи результати. Кнопка головного меню в check-in дозволяє вийти; чернетка залишається в базі. Основна клієнтська клавіатура налаштована як постійна.

## Замовлення й оплата

Для замовлення потрібна активна терапія. Вартість: ціна за тиждень × кількість тижнів зі знижкою.

| Період | Знижка |
| --- | --- |
| 1 тиждень | 0% |
| 2 тижні | 10% |
| 4 тижні | 20% |

Клієнт обирає відділення, поштомат або адресну доставку, перевіряє дані та отримує реквізити. Після кнопки «Оплачено» надсилає PDF або зображення JPG/JPEG, PNG чи WEBP. Замовлення створюється після завантаження квитанції.

| Статус у базі | Назва в інтерфейсі |
| --- | --- |
| `new` | Нове |
| `processed` | Оплату підтверджено |
| `completed` | Завершено |

Адміністратор перевіряє квитанцію вручну. Перехід до «Оплату підтверджено» надсилає клієнту повідомлення про обробку замовлення й очікування повідомлення Нової пошти. Якщо Telegram повертає помилку доставки, адміністратор отримує пояснення; статус оплати залишається збереженим.

Інтеграції з банком чи API Нової пошти немає: бот не перевіряє переказ автоматично, не створює накладні та не відстежує доставку. Зазначені в текстах 24 години — умови обробки, повідомлені клієнту, а не автоматичне завдання відправлення.

## Check-in та розклад

Планувальник використовує **Europe/Kyiv**:

- Перевірка запланованої терапії — кожні 2 хвилини й одразу після запуску.
- Запрошення на check-in — щодня о 10:00 та перевірка належних запрошень після запуску.
- Перший автоматичний check-in — через 7 днів після реєстрації, якщо не заданий інший строк у базі.
- Після завершення наступний check-in доступний через 7 днів.
- Незавершене опитування нагадується щодня; успішне нагадування фіксується в базі.

Чернетки й завершені відповіді зберігаються в SQLite. Діалоги реєстрації, оформлення замовлення та інші FSM-стани зберігаються в пам’яті й скидаються після перезапуску. Для продовження чернетки check-in відкрийте його запрошення знову.

## Структура

```text
main.py                 запуск, сервіси, маршрути та планувальник
config.py               налаштування і шлях до бази
app/
  assets/               шаблон прогресу та шрифти
  database/             схема SQLite й репозиторії
  filters/              перевірка адміністратора
  handlers/admin/       сценарії панелі лікаря
  handlers/user/        клієнтські сценарії
  keyboards/            клавіатури Telegram
  models/               моделі даних
  scheduler/            фонові завдання
  services/             логіка терапії, замовлень, check-in
  states/               стани діалогів
  texts/                спільні тексти й форматування
  utils/                перевірки введення та зображення
data/                   база db.db
.env.example            приклад конфігурації
requirements.txt        зафіксовані залежності
Dockerfile              образ Python 3.14
docker-compose.yml      запуск і зберігання даних
```

Частина текстів міститься в обробниках. Повідомлення використовують Telegram HTML: `<b>` — жирний, `<i>` — курсив. Довільне введення в повідомленнях потрібно екранувати через `html.escape`.

## Обслуговування та перевірки

Перед оновленням зробіть копію `data/db.db`. Для узгодженої копії зупиніть бота, скопіюйте базу й запустіть його знову. Відновлюйте базу при зупиненому боті. У Docker працюйте з папкою `data` на хості.

База містить персональні дані та відомості про терапію: обмежте доступ до неї та резервних копій. Квитанції зберігаються як Telegram `file_id` з типом і назвою файла, а не як локальні PDF або зображення.

Перевірка середовища та синтаксису на Windows:

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m compileall -q app main.py config.py
```

На Linux/macOS використовуйте `.venv/bin/python`. Окремого автоматичного набору тестів у поточному робочому дереві немає. Перевірка синтаксису не замінює перевірку сценаріїв у Telegram.

Після змін перевірте профіль, повернення до меню, пагінацію, створення дозування, призначення, check-in, замовлення з квитанцією та підтвердження оплати. Для перевірки оформлення без переказу коштів установіть `PAYMENT_TEST_MODE=true` і тестові реквізити.

## Типові проблеми

| Симптом | Що перевірити |
| --- | --- |
| `KeyError` при запуску | Наявність `.env` та обов’язкових змінних. |
| Помилка `DOCTOR_ID` | Значення має бути одним цілим числом, не username. |
| `unable to open database file` | Папку `data` та права на запис. |
| `/admin` не відповідає | Telegram ID у `DOCTOR_ID`, перезапуск після зміни `.env`. |
| Конфлікт отримання оновлень | Інший процес із тим самим токеном; залиште один екземпляр. |
| Зникли кнопки чи перервано діалог | Надішліть `/menu` або `/admin`. Старі повідомлення після зміни коду не оновлюються. |
| Немає доступної терапії | Створіть дозування і призначте пацієнту; майбутнє призначення ще не активне. |
| Не створюється зображення прогресу | Файл `app/assets/progress_template_new.png` та шрифти `BalsamiqSans-Bold.ttf`, `BalsamiqSans-Regular.ttf` у `app/assets/fonts`. |
| `ZoneInfoNotFoundError` | Установлення всіх залежностей, зокрема `tzdata`. |
| Не доставлено сповіщення | Чи не заблоковано бота; помилки процесу або `docker compose logs bot`. |

При запуску бот видаляє webhook і відкидає накопичені Telegram-оновлення (`drop_pending_updates=True`). Повідомлення, надіслані під час простою, можуть не обробитися — їх потрібно надіслати повторно.
